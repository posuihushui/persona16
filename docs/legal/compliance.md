# 合规红线

`compliance-reviewer` 对全仓所有面向用户的内容有一票否决权。这份文档是它的判断依据。
`npm run check:compliance` 是机器辅助，脚本通过不等于人工审查通过。

## 一、商标与版权

**MBTI® 是 The Myers-Briggs Company 的注册商标。** 在中国大陆，第 41 类和第 44 类均有相关注册。商业性使用该标识做产品名、页面标题、投放素材标题或视频口播，存在商标侵权风险。经典的 93 题题库文本同样受著作权保护。

因此本项目的处理是：

| 可以用 | 不可以用 |
| --- | --- |
| 「16 型人格测试」作为产品名 | MBTI、Myers-Briggs、迈尔斯·布里格斯 |
| 内外向、实感直觉、思考情感、判断感知的四维度框架（源自荣格心理类型理论，属于公共知识） | 官方题目文本 |
| 自己撰写的题目和类型描述 | 官方类型描述文本 |
| 自己命名的类型别名（压舱石、远眺者等） | 第三方产品的类型别名（建筑师、提倡者等） |

投放素材同样适用。搜索流量的诱惑在于用商标词做标题，这个诱惑必须拒绝。

`check:compliance` 会扫描 `content/`、`src/`、`docs/operations/`、`public/` 拦截这些词。平台侧的投放文案不在仓库里，需要人工按同一清单过一遍。

## 二、广告法

《广告法》第九条禁止绝对化用语。以下表达在本项目属于阻断项：

- 「最准」「最专业」「最权威」「最科学」
- 「全网第一」「全国第一」
- 「国家级」「世界级」「顶级品质」
- 「100% 准确」「100% 有效」
- 「权威认证」「官方认证」（除非确有可出示的资质）

付费页的承诺清单必须与实际交付一致。`paywall.json` 的 `promise` 每一条都要能对应到 `paid` 字段里真实存在的内容。承诺了没给，属于虚假宣传，不只是体验问题。

## 三、心理表达边界

本站是自我认知娱乐工具，不是心理健康服务。越界的表达会同时触发平台举报和监管风险。

**禁止：**

- 诊断、治疗、治愈、疗效
- 疾病与症状名称：抑郁症、焦虑症、强迫症、双相、精神分裂
- 宿命论：「你注定」「你永远不会」「性格不可改变」
- 能力评价：把类型和智商、情商、成功概率挂钩

**必须：**

- 每个测试的 `meta.disclaimer` 必须存在且在落地页和结果页可见。
- 免责声明必须包含求助资源。当前使用全国心理援助热线 12356。
- 缺点部分必须落在可改善的具体行为上，不做人身评价。

## 四、个人信息

适用《个人信息保护法》。本项目的策略是尽量少收，少收就少了大部分合规成本。

**当前实际收集：** 作答内容、匿名浏览器标识、微信 openid（仅付费时）、行为埋点、支付订单信息。

**明确不收集：** 姓名、身份证、手机号、住址、生物特征、精确定位。

**规则：**

- 隐私政策必须覆盖实际收集的每一项。新增任何收集字段，同步改 `src/app/legal/privacy/page.tsx`。
- 不做用户画像外售，不与第三方广告平台共享作答明细。
- 用户可凭找回码要求删除作答与订单，删除后只保留支付审计线索。
- 未满 14 周岁需监护人同意，隐私政策已声明。

## 五、平台规则

微信外部链接内容管理规范和抖音的相关规则都禁止诱导行为。

**禁止：**

- 分享后解锁、集赞、强制转发到群
- 关注公众号才能查看结果
- 强制跳转下载
- 恐惧营销（「不测你就会怎样」）
- 虚假稀缺（「仅剩 3 个免费名额」）

本项目从产品设计上就不做这些，不是靠运营自觉。免费结果对任何持链接的人可见，这是原则 1。

## 六、豁免机制

运营和法务文档需要引用禁用词原文，这些行会被 `check:compliance` 误判。豁免方式：

- 行级：在该行任意位置写 compliance-allow
- 区块级：用 HTML 注释 compliance-allow:start 和 compliance-allow:end 包住若干行

**豁免只允许用于规则原文引用。** 任何面向用户的文案加豁免都是滥用，审查时如果发现 `content/` 或 `src/` 下出现豁免标记，直接判为阻断项。

## 七、审查产出格式

`compliance-reviewer` 的每条结论必须包含：

1. 位置：文件路径加行号
2. 违反的具体规则：引用本文档的条目
3. 严重程度：阻断上线 / 上线前修 / 建议优化
4. 修改建议

阻断项没修完不签字。上线前的最后一遍审查覆盖：首页、落地页、结果页、付费页、报告页、隐私政策、用户协议、当期投放素材。

## 八、上线前必须确认的事实项

这几项无法由脚本判断，必须人工确认并记录：

- [ ] 运营主体名称与营业执照一致，已配置到 `LEGAL_ENTITY_NAME`
- [ ] 域名 ICP 备案号真实有效，已配置到 `LEGAL_ICP_NUMBER`
- [ ] 客服邮箱真实可达，有人处理，已配置到 `LEGAL_CONTACT_EMAIL`
- [ ] 退款流程真实可执行，不是写在协议里的空话
- [ ] 微信支付商户主体与运营主体一致
- [ ] 隐私政策的收集清单与代码实际行为逐项核对过
