# PRD v1 · 16型人格测试

## 目标用户与场景

主要来自微信和抖音的社交流量，不是搜索流量。典型场景有两个：

**场景一，被朋友的结果页勾住。** 用户在群里或朋友圈看到某人晒的类型卡，好奇自己是什么，点进来测。这条路径的关键是结果页本身要好看到值得截图。

**场景二，刷到短视频。** 用户在抖音看到人格类型相关内容，点主页链接或评论区链接进来。这条路径的关键是落地页三秒内说清楚这是什么、要花多久。

用户画像偏年轻，18 到 30 岁为主，对自我认知类内容有兴趣，对「测出来准不准」有判断力，会因为描述写得敷衍而直接关掉。

## 一句话价值主张

用 48 道具体情境题，换一份写给你本人而不是写给所有人的性格描述。

## 用户旅程

1. **落地** — 进入 `/t/persona16`。看到测试名、一句话卖点、题量与时长、测完能拿到什么。免责声明在首屏可见。
2. **答题** — 进入 `/t/persona16/quiz`。一屏一题，选完自动进下一题，顶部有进度条。中途退出进度存在本机，回来能接着答。
3. **出结果** — 提交后跳到 `/r/<attemptId>`。首屏是类型卡：类型码、类型名、人设标签、三个关键词。这是用户会截图的部分。
4. **读免费部分** — 四条轴上的位置和强度是完整的，性格描述给开头一段后渐隐。用户已经拿到确切的结论。
5. **分享** — 复制链接按钮加截图引导。分享不解锁任何内容，只能换到深度报告的折扣。
6. **付费** — 付款界面列出锁住的十项内容、价格与折扣、倒计时、退款说明。价格由服务端算。
7. **读深度报告** — 支付回调确认后进入 `/r/<attemptId>/report`。底部给出找回码。
8. **找回** — 换设备后在 `/retrieve` 输入找回码重新打开报告。

## 免费与付费边界

| 内容 | 免费 | 付费 | 理由 |

| 类型码与类型名 | ✅ | | 这是分享物料，卡住它等于卡住获客 |
| 人设标签与三关键词 | ✅ | | 同上 |
| 四条轴上的位置与强度 | ✅ | | 用户判断「准不准」的依据，也是结果的结论本身 |
| 性格描述的开头一段 | ✅ | | 约 62 字，让用户知道文风和精度值不值这个价 |
| 完整性格描述 | | ✅ | |
| 最舒服 / 最容易累的状态 | | ✅ | |
| 认知偏好拆解 | | ✅ | |
| 五条优势 | | ✅ | |
| 五条盲点 + 改善动作 | | ✅ | 可执行性是付费的核心理由 |
| 职业环境匹配 | | ✅ | 决策价值最高的一块 |
| 亲密关系表现与摩擦 | | ✅ | |
| 与其他类型相处提示 | | ✅ | |
| 三条成长建议 | | ✅ | |

**免费给的是结论，付费卖的是深度。** 用户不付钱也能拿到一个确切的答案：我是什么类型，我在四条轴上偏到哪。被截断的是描述的厚度，不是结论本身。

预览长度写在 `paywall.json` 的 `teaser.chars`，校验脚本会拦住超过最短正文六成的配置，避免预览长到等于把付费内容公开。

### 定价与折扣

定价 9.9 元，划线价 19.9 元。

裂变机制：把结果分享出去可领 24 小时 6 折券，折后 5.94 元。规则写在 `paywall.json` 的 `discount`：

| 字段 | 含义 |
| --- | --- |
| `percent` | 折后按原价的百分之多少收，60 即六折 |
| `windowHours` | 有效期小时数 |
| `trigger` | `share` 需要用户主动分享，`timed` 是纯限时促销不绑定行为 |

**价格全部在服务端算。** 客户端既不发送价格也不发送折扣码，下单时重新算一遍，不复用展示过的报价。券绑定领取时的会话，一次作答只发一张，反复点分享不刷新有效期。

**分享不解锁任何内容。** 免费能看到的东西在分享前后完全一样，分享换到的只是价格。这是和「分享才能看结果」的本质区别，也是这个机制能做的上限。

## 传播机制

**用户为什么会转发：** 因为类型卡上那句人设标签写得准且好玩，转发它等于表达「这就是我」。不是因为被卡住。

**转发时说什么：** 用户自己的话。我们提供的是好截的图和好复制的链接，不提供强制话术。

**明确不做：** 分享解锁、集赞、强制关注、分享给 N 个好友。这几件事既违反微信规则，也违反产品原则 1。分享换折扣不属于这一类，它不锁任何内容，风险与应对见 `docs/operations/wechat-distribution.md`。

## 指标与合格线

| 指标 | 定义 | 合格线 | 埋点 |
| --- | --- | --- | --- |
| 开始率 | 落地页到点击开始测试 | ≥ 55% | `landing_view` → `quiz_start` |
| 完成率 | 开始到提交出结果 | ≥ 65% | `quiz_start` → `quiz_complete` |
| 结果页分享率 | 结果页到点击复制链接 | ≥ 8% | `result_view` → `share_click` |
| 付费转化率 | 结果页到支付成功 | ≥ 2% | `result_view` → `order_paid` |
| 下单支付成功率 | 创建订单到支付成功 | ≥ 70% | `order_create` → `order_paid` |

完成率是第一优先。48 题在移动端偏长，如果完成率低于 55%，先考虑分段展示或缩减题量到 36 题，而不是先动付费点。

分享率是第二优先，它决定获客成本。分享率低说明类型卡写得不够好，回到内容而不是加分享按钮。

## 不做什么

- 不做账号注册和登录体系。匿名优先。
- 不做订阅制。权益粒度是单份报告。
- 不做小程序。第一版只做 H5。
- 不做题目自适应或题库随机抽取。固定题序保证结果可复现。
- 不做类型排行榜和用户之间的匹配社交。这会引入大量内容审核成本。
- 不收集生日、性别之外的任何画像字段，第一版连这两项也不收集。

## 风险与依赖

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| 微信拦截域名 | 分享链路直接断掉 | 域名池 + 兜底引导页，见 `docs/operations/wechat-distribution.md` |
| 抖音内置浏览器无法唤起微信支付 | 抖音来源用户无法付费 | 显式引导跳转，不静默失败 |
| 预览太短导致用户觉得被套路 | 分享率和口碑双输 | 结论（类型码与四条轴）永远完整免费，只截描述。预览长度有校验上限 |
| 分享换折扣被判利益诱导 | 域名被限制访问 | 盯举报量，必要时把 `discount.trigger` 切成 `timed` |
| 报告写得像万金油 | 分享率和口碑双输 | `/content-review` 的可替换性自查是硬门槛 |
| 商标风险 | 法律风险 | 全站不出现 MBTI 与相关商标，`npm run check:compliance` 拦截 |

## 需要 compliance-reviewer 提前介入的部分

- 结果页所有类型描述的宿命论表达和能力评价表达
- 落地页和投放素材的绝对化用语
- 隐私政策与实际收集字段的覆盖关系
