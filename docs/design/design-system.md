# 设计系统

令牌定义在 `src/app/globals.css`。组件里不写死颜色和字号，一律用变量。

## 设计立场

这是一个会被截图发朋友圈的产品，所以视觉的第一目标不是「好用」，是「值得被看见」。结果页首屏承担获客职责，它的设计优先级高于站内任何页面。

同时它卖的是一份认真写的报告，所以整体气质要偏克制和可信。正文用清晰的排版和留白，结果卡使用柔和的固定色板与类型几何，让视觉重量集中在用户要截图的那块。入口和阅读区用青绿色手绘人物场景，先让用户认出熟悉的生活，再进入维度与描述。

## 图形优先

这是给微信和抖音用户的测试站，用户没有耐心读长段落。排版的第一原则是：
**用户不读任何一段完整文字，也应该知道这一页在讲什么、下一步该点哪里。**

具体做法：

- **首屏不放长段落。** 落地页首屏用情境插画、标题、简短提示、三个数字和开始按钮说明价值；移动端插画压到 184px，短屏进一步缩小，主操作优先可见。
- **能画就不写。** 四个维度画成两端带标签的轴，16 个类型排成矩阵，工作环境画成两栏对比，成长建议做成编号卡。
- **长文本折叠。** 用原生 `<details>`，折叠状态下内容仍在 HTML 里，搜索和 AI 抓得到，用户不用滚过去。
- **每块内容有图标锚点。** `SectionHead` 给长段落一个视觉入口，让眼睛知道在哪停。
- **图形必须携带信息。** 维度轴和类型几何从内容包数据生成；生活情境插画由 `content/illustrations.json` 声明语义、替代文本和页面位置，随内容一起维护。情境插画只帮助理解段落主题，不表达个人得分，也不替代真实的四维位置。

## 主视觉

16 只类型动物，一个类型一只。侧身站在同一条地面线上，手里拿着一件说明它做什么的道具。
扁平矢量：一个剪影、两三块色、一圈深色描边，边缘补几笔短线做手绘感。
纸色和情境插画同一张，两套图放在一页上才是同一个世界。

**为什么不是抽象几何。** 上一版是包豪斯套印的构成，四个字母各控制主形的一个属性。
它在海报尺寸上成立，但矩阵页缩到 44px、配对卡缩到 40px 时，
所有差异都挤在「方还是圆、大还是小」上，同色系四张几乎认不出区别。
换成动物之后，长耳、长颈、壳、鳍这些剪影在小尺寸下依然分得开，
用户也会记住「我是那只水獭」——抽象色块记不住。

**动物是原创的，道具跟着类型标签走。** 内燃灯提灯、点灯人挑着长杆上的灯、
远眺者架望远镜、思维矿工戴矿灯拿镐、拆解手拿扳手、织网人抱线团。
标签在 `content/tests/persona16/results/*.json` 的 `label` 字段，改标签时要回头看这只动物还对不对。

| 组 | 类型与动物 |
| --- | --- |
| NF 藕粉 | INFP 兔 · INFJ 鲸 · ENFJ 马 · ENFP 松鼠 |
| NT 雾蓝 | INTJ 鹤 · INTP 章鱼 · ENTP 鹦鹉 · ENTJ 犀牛 |
| ST 鼠尾草 | ISTJ 龟 · ISTP 水獭 · ESTJ 公牛 · ESTP 袋鼠 |
| SF 陶土 | ISFJ 河狸 · ISFP 猫 · ESFJ 蜜蜂 · ESFP 火烈鸟 |

**四肢用「先描边再填色」画，不要用分开的形去拼。** 所有笔画先用描边色画一遍粗的，
再用身体色画一遍细的，两遍之间不穿插。用矩形拼腿试过一版，四条腿会各自飘在身子外面接不上。
`limbs()` 就是干这个的，腿、脖子、触手、尾巴都走它。

**道具色是固定的暖金，不跟色系走。** 试过按色相取补色，藕粉那组补出来是草绿，
灯和橡果全成了绿的，和身体颜色直接打架。固定成暖金之后每张图的视线落点一致，整套也更像一套。

**小尺寸换一个更紧的视框。** 画布 400×400，角色四周留了一圈纸。
这圈留白在海报上是对的，但 40px 的时候会把本来就小的角色再缩掉一截。
`TypeArt` 在 80px 以下改用 `32 44 340 340`。改动物的姿势时别让道具越过这个框。

**色板必须柔和。** 饱和度全部压在 36% 以下。高饱和在手机上显得廉价，
也压不住大面积铺色。按 SN × TF 分成四个色系共享色相：雾蓝、藕粉、鼠尾草、陶土，
组内再按 E/I 与 J/P 分四档，避免撞色。角色本身的饱和度比 `toneFor` 高一档：
那套是给大面积铺色用的，角色是小面积填充加深色描边，用同样的饱和度会灰掉。

**套印色只压明度不转色相。** 转色相会让暖色系整体发脏，陶土会直接飘成橄榄绿。
压明度也要克制，暖色压太深就变成褐色，靠提饱和拉开层次。

**主视觉的颜色不跟随主题令牌。** 它会被截图外发，深浅色模式下必须长得一样。
所以海报卡在深色模式里仍然是浅底，这是有意的，看起来也更像一件作品。

**海报上的小字用 `tone.ink`，不用套印色 `tone.deep`。** 套印色的明度随色系在 38% 到 70%
之间浮动，16 个类型里有 10 个拿它当 11px 小字的颜色达不到 4.5:1，最差的两个只有 2.2:1。
`tone.ink` 的明度固定 34%，全部在 4.9:1 以上。同理，海报上承载信息的小字不再降透明度——
最差的那一组本来就没有余量，压到 0.6 会掉到 2.3:1。这条由 `scripts/poster.test.mts` 盯着。

**但类型色板只能做填充，不能做文字的底。** 它是一组固定的浅色，而卡上的文字用主题令牌——
拿它当卡片底色，深色模式下就是浅底配浅字。类型卡和关键词瓦片试过一版这样的写法，
改成「底色与文字走令牌，类型色只留在左边那条色条和标记上」之后两套色系才互不干涉。
海报是例外：它整块都是固定色，文字颜色也从同一套色板里取。

**画面以字符串形式产出。** `typeArtMarkup()` 返回 SVG 内容，React 组件和
`/api/og` 分享卡共用同一份。两边各画一套迟早会对不上，
而分享卡和结果页长得不一样是很难被发现的那类问题。

## 类型目录页

这一页要同时干两件事：让人快速找到自己那一格，和让人读懂每一格是什么。
两件事都用「16 个类型的列表」来做，所以关键是让它们长得不一样。

- **上面是地图，下面是目录。** 地图是 4×4 矩阵，格子里只有主视觉和类型码，压在一张比页面深一档的底上；目录是一列卡片，有名字和那句话，白底。两块曾经都是白底圆角框、同样 44px 的图，读起来就是把 16 个类型倒了两遍——这是这一页最早的问题。
- **地图不放中文名。** 名字在下面的目录里。地图只回答「我在哪一格」，目录才回答「这一格是什么」，各自只做一件事。格子里没有中文名之后链接文字只剩类型码，所以补 `aria-label`。
- **轴名写成横排文字放在矩阵上下。** 竖排要靠 `writing-mode` 或旋转，老内核上容易错位。
- **目录始终一列。** 这一页的容器封顶 30rem，两列每张卡只剩 210px 放文字，那句话必然折三行，一行几张高度全不一样。一列之后每张卡一行一句，主视觉也放得下 60px。
- **筛选按轴成对。** 九个 chip 平铺时最后一个会单独掉到下一行，看着像漏掉的。一条轴的两个字母包在一个胶囊里整对换行，顺手把「同一条轴上只能选一边」画出来。
- **筛空的组连标题一起收起来。** 只收卡片的话，选中 E 之后 IJ 和 IP 两个标题还立着，下面什么都没有。

## 类型解读页

类型页是站内最长的一页，也是搜索和投放的落点，所以它的排版单独定了一套：

- **按用户会搜的问题分节。** 平时什么样、长处与难处、恋爱、友谊、工作、写在最后。章节由内容包声明，页面按顺序渲染。
- **每节开头是「图 + 编号 + 标题 + 一句结论」。** 不读正文的用户扫完这四样也知道这一节说了什么。
- **版式按这一节有什么来轮换。** 六节如果都是同一个模子，读到第三节时版面已经不提供任何「我读到哪儿了」的信息。有对照栏的不出图（两栏本身就是画面），有并列短句的用铺满头图，其余几节的图左右交替。规则写在 `src/lib/prose.ts` 的 `chapterLayout`，只看内容形状，不认识具体类型码；内容包可以用 `layout` 覆盖。
- **那句结论做成引用卡。** 主色左边框加浅底，比一行粗字更容易在滑动中被抓住。
- **窄屏吸顶目录，宽屏常驻侧栏。** 960px 以下用可横滑的胶囊条加一条阅读进度线；960px 以上换成左侧目录、右侧正文的两栏，正文宽度到 1280px 封顶，中文一行不超过 40 字左右。
- **免费与付费的分界写在页面语气里。** 这一页写「他们」，付费报告写「你」。用户读完知道这一类人大概什么样，但不知道自己偏到哪一步。

## 动效

动效做四件事：说明层级关系、让长页面看起来是活的、指出下一步往哪走、让点击有回应。不做入场表演。

| 位置 | 做法 |
| --- | --- |
| 首屏 | 类型卡与标题依次淡入上移并轻微放大，520ms，错开 120ms |
| 长页面 | 每节进入视口时整块淡入上移 22px；节内的图、标题、正文再依次进场，每个差 70ms |
| 目录 | 当前小节高亮时弹一下，进度线跟随滚动 |
| 「下一节」 | 箭头持续轻推 4px，告诉用户还能往下走 |
| 插画 | 每张图三到五处动作：人物起伏 8px、挥手摆 28°、眨眼、太阳转、云飘、心跳、水滴落下 |
| 可点元素 | 桌面悬停抬 2px，移动端按下压 1px |

**幅度是调过的。** 第一版按 2–6px、3–8 秒做，实际效果是「要盯着看才发现在动」，等于白做。现在人物起伏 8px、周期 2.6 秒，摆动到 7–8 度，心跳一轮 1.8 秒——扫一眼就知道页面是活的，但没有一处动作会把视线从正文上拽走。

`prefers-reduced-motion: reduce` 时全部关掉，包括插画里的动作、进入视口的淡入和箭头。关掉之后页面内容完全一致，没有任何信息只由动画表达。

## 情境插画

生活场景是扁平矢量：圆角形体、彩色人物、六个色系各管一张图。人物动作和道具解释精力恢复、观察信息、做出选择、安排节奏、成长及沟通，避免只有装饰意义的摆件。每幅图保持足够留白，缩小后仍能识别人物关系与关键物件。图内不放文字，不把某一种偏好画成更高、更强或更正确——同一张图里的两个人永远同样鲜亮。

插画有自己的色系，和品牌靛蓝、类型色板互不干涉：按钮和类型主视觉仍然克制，插画负责让页面有精神。章节头图铺满正文宽度（8:5），卡片里的图按位置在 104–216px 之间。

完整资产清单、布局约定与维护说明见 [illustrations.md](./illustrations.md)，原创生成提示词见 [illustration-prompts.json](./illustration-prompts.json)。原有 16 种类型几何及分享海报保持同一套语义，情境插画不改变它们。

画面自 2026-09-08 起是内联 SVG：扁平矢量、圆角形体、同一套青绿色，随 HTML 到达，不再产生图片请求，任意尺寸都清晰。清单里仍可声明位图资源，`SceneIllustration` 会走 `<picture>` 分支，WebP 优先、PNG 兼容旧版 iOS。

图像纸色固定为 `--scene-paper`，深浅色模式下均保持原画；外围卡片和文字使用主题令牌。青绿是内容插画色，主按钮继续使用品牌靛蓝，维度两极继续使用同一色系，不把插画颜色当作答案提示。

## 分享卡与结果页海报

两个渲染目标，一份模型。结果页那张是 HTML，要响应式、可选中、有正确的标题层级；
`/api/og` 那张是固定 900×1200 的 SVG，被塞进 `<img>` 再画进 canvas 转成 PNG。
强行让两边输出同一段标记，会把网页那张拖成一张不能换行的图，所以合的是**模型**：
卡上有哪些块、什么顺序、文字怎么断行、色条填到哪、印章和走马带写什么，
全部由 `src/lib/poster.ts` 算出来，两个渲染器只负责画。几何、印章、走马带这几块纯图形
直接共用同一段标记。真正会出问题又很难被发现的是「两边卡上的东西不一样」，不是差几个像素。

**两张卡的分工不同。** 结果页那张印着本人的四条轴，是用户自己截图用的；
`/api/og` 那张是公开类型卡，会被转发出去，所以不含任何一次作答的数据——
没有四条轴的位置，也没有 attemptId。公开卡上画位置会被读成转发者的作答。

| 卡上的块 | 结果页 | 公开分享卡 |
| --- | --- | --- |
| 深色块、信条、类型码与名字、主视觉、口语标签、骑缝章、走马带 | 有 | 有 |
| 本次作答的四条色条 | 有 | 没有 |
| 来源域名 | 有 | 没有 |
| `label` 那句话 | 没有 | 没有 |

**构图：一块深色，主视觉压住它的下缘。** 上面一整块深色装品牌小字、信条、类型码和类型名，
主视觉往上提压住色块下缘，底下浅色区放四条轴和口语标签，最后一条走马带收口。
第一版是「主视觉在上、文字在下」两段平铺，类型码没有地方做大，右半边空着一整片，
整张卡读起来是一份文档而不是一张海报。压边之后画面才有前后关系。

**主视觉必须保持方形，不能横向满幅。** 量过 16 只动物在 400 见方里的占位：
横向都落在 30 到 377 之间，纵向最高的到 33、最矮的只到 174。横向铺满就得纵向裁切，
会把高的那几只切掉。四周固定留白可以裁掉每边 22 个单位，画面能大一成，再多就切到内容。
各自上方还剩多少空当取决于那只动物画得多高，那是画本身的比例，版面不逐类型去调。

**`label` 不上卡。** 卡上已经有信条了，两句话都是「一句话说清这类人」，
连着出现就是同一件事说两遍。`label` 留在类型页和紧凑形态的头图里。
信条与 label 的字面重复由 `npm run check:content` 拦截。

**骑缝章是一枚金币，不绕排文字。** 试过一圈绕排品牌名，但那行字在卡上只有 12px，
转成 PNG 再被压一道之后糊成噪点，而且有一半是倒着的。现在是实心圆加一道内圈细线加一个大字，
在卡上 124px、在结果页 52px 两个尺寸都认得出来。品牌名在卡的左上角已经出现过。

**四条轴画成色条而不是写成一行文字。** 从中线往命中那一端填，填多少就是偏多少。
两端必须同色：站内橙色代表消耗、蓝色代表舒服，而这四条轴的两极没有好坏之分。

**走马带和骑缝章是纯装饰，只允许出现在海报上。** 站内其他地方仍然是「能画就不写、
图形必须携带信息」；海报是全站唯一以被截图外发为目标的区域，那里「值得被看见」
压过「克制」，所以这两样在这里成立，换到阅读页就不成立。

**品牌金只用在骑缝章上。** 类型色板整体压在 36% 饱和度以下，但海报需要一个能跳出来的重音。
16 张卡共用同一个高饱和色，一个亮点比 16 套吵闹的配色更像一个系列。

**排版靠算，不靠试。** 标签贴着走马带从底往上排，所以永远压不到带子上；
万一上下两块还会碰，从后往前减标签条数直到排得下。宁可少两条标签，也不能让两块字叠在一起。
这些不变量由 `scripts/poster.test.mts` 对 16 个类型逐一验证——
这张卡排错了不会报错，只会安静地画歪，而它正是最容易被外发出去的那张图。

## 海报排版

头图是全站唯一以「被截图外发」为设计目标的区域，排版要有层次，不能只是把字堆上去：

- 顶部小字拉到 0.24em 字距，做成标签感，和下面的大字形成对比
- 类型码是主角，3.75rem，字距收到 -0.035em，行高压到 0.92
- 中间一条 2.25rem 的短线断开标题区和描述
- 描述用更大的字号和更松的行高，是给人读的，不是标签

窄屏（359px 以下）把类型码收一档，避免四个字母换行。

结果页和公开类型页使用 `TypePoster` 的紧凑布局：主视觉保持完整正方形几何，以 160px（窄屏 136px）呈现；缩短留白，让类型码、标签、关键词和下一步在首屏可见。结果页下一步是保存卡片 / 复制链接，类型页下一步是开始自己的测试。

个人四维轴同时显示两极百分比，点位置使用真实作答结果。公开类型页仅说明类型偏向，必须写明「示意位置，不代表你的实际作答」，不展示伪造的个人百分比。

付费清单是四张卡的网格，其余六项收进原生 `details`。十行等长的带锁文字读到第四行就会被跳过，摆成网格之后每一项是一张卡，扫一遍就知道报告里有几块内容。卡上只有 `paywall.json` 里 `locked` 声明的标题和钩子，付费正文仍在服务端截断。

网格上方再放一张 `ReportSkeleton`：报告的版式骨架，只有灰条，画的是「有封面、有阶梯、有双栏、有带动作的卡」。里面没有一个字是正文——不是打码，是真的没有内容。

**为什么用光谱而不是进度条。** 进度条会被读成「你得了多少分」，但这四个维度不是打分，是你落在两极之间的哪个位置。两端都标出来，用户一眼就明白这不是考试成绩，也不会觉得偏向某一极是「分数低」。

**两极不能用不同色系。** 站内橙色代表「消耗」，蓝色代表「舒服」。轴的两端必须同色，否则会暗示某一极更差，而四条轴的两极都没有好坏之分。

**图标全部内联 SVG。** 用 `currentColor` 描边，深浅色自动跟随，不加载字体图标也不加载图片，符合国内环境的零境外资源要求。

## 深度报告

报告是全站文字最密的一页，八千多字。原来它是「小标题 + 段落或项目符号」从头铺到尾，
所以排版按内容自己的形状分工：

| 这块内容的形状 | 怎么摆 |
| --- | --- |
| 认知偏好本来就有次序 | 顺位阶梯，序号加一条越往下越短的带子 |
| 优势是五条并列结论 | 编号卡，前半句结论加粗，后半句解释降一级 |
| 盲点是「看到的 + 要做的」 | 双格卡，动作那格可以勾掉 |
| 相处对象有两个类型码 | 配对卡，双方主视觉并排，左边永远是本人 |
| 岗位方向是一组并列短语 | 瓦片，不用挤成一行 chip |

**结论与解释的拆分由文本自己决定。** `src/lib/prose.ts` 按第一个逗号或句号切，
带长度闸门；切不动的条目原样整条显示。所以这套排版不依赖内容包新增字段，
也不会因为版式把文字吃掉。

**阶梯的带子表示顺位，不表示分数。** 四条轴的位置由光谱负责，报告开头的封面里已经有一份，
阶梯旁边的说明会写明这件事。

**顶部有封面和目录。** 封面是紧凑海报加四条轴，读者一打开就知道这份报告是给谁的，
后面所有的「你」都挂在那张卡上；目录复用类型页的吸顶条。

## 答题界面

48 道题意味着同一个界面要被看 48 次，任何一点多余都会被放大 48 倍。

**只留三样：** 进度条、题干、选项。计数器和进度条重复，去掉一个；下一题按钮和自动进入重复，去掉；底部提示只在第一题出现，之后用户已经知道怎么答了。

页面顶部可以有一幅 48px 的通用自我观察情境图，不随当前题目或维度变化，避免提示作答方向。视口高度不超过 680px 时隐藏这一辅助行，保证题干、五个选项和返回入口优先可见。

**切题是即时的。** 点下去当帧换题，实测 5 到 8 毫秒。不做「先淡出再淡入」的两段式，理由有两个：

1. 每题多等 170 毫秒，48 题累计白白多花 8 秒。
2. 两段式依赖定时器。页面被挂起或机器卡的时候，浏览器会把定时器节流到一秒开外，用户点了没反应。实测在后台标签页里就是 1000 毫秒。

顺滑靠入场动画完成：新题从侧面滑入并淡入，240ms 缓出。首击即时生效，之后 240ms 内重复点击不计入下一题，避免双击跨题；不依赖后台计时器解锁。

**题干区固定两行高度。** 题干上限 30 字，在 375px 宽下正好两行。单行题也占同样的位置，选项因此不会上下挪。实测 48 题里选项顶部始终在同一个像素上。

**动画只用 transform 和 opacity。** 这两个属性走合成层，在国产内核的中低端机上也不会掉帧。改成动 height 或 top 会直接触发重排。

**进度恢复在绘制之前完成。** 用 `useLayoutEffect`，回头继续答的用户不会先看到第一题再跳走。服务端没有 localStorage，SSR 时退化成普通 effect。

恢复前校验版本、题目 ID、量表值与索引。有效进度显示「继续作答 / 重新开始」，重置前在页面内确认。不能保存时明确提示；提交失败保留答案并提供重试，提交中禁止重复发送。

**尊重 `prefers-reduced-motion`。** 开了这个偏好的用户直接切，不做任何位移。

## 基准

- 移动端优先，基准视口 375px，同时验证 320 × 568 短屏。答题和报告内容区最大宽度 30rem；首页与测试介绍页在 640px 以上可扩到 54rem，用双列图文与多列场景卡承接插画。
- 一屏一题，选项高度 3.25rem，拇指区可达。
- 不出现横向滚动。宽内容自己滚，页面不滚。
- 对比度满足 WCAG AA。

## 色彩

浅色底是暖白 `#fbfaf7`，不是纯白。纯白在微信内置浏览器里偏刺眼，暖白更接近阅读材料的感觉。

主色是靛蓝 `#5b6abf`。选它是因为它足够冷静，不像红橙那样有促销感，同时在深色背景上做渐变仍然有辨识度。

深色模式不是把颜色取反，是重新定义一套令牌。深色下主色提亮到 `#8b96e0`，否则在深底上对比度不够。

颜色只在 `:root` 和 `prefers-color-scheme: dark` 里定义。任何组件里出现十六进制色值都是错误。

## 分层

只有三层。任何新块都必须落在其中一层，不许自己发明第四种底色。

| 层 | 令牌 | 用在哪 |
| --- | --- | --- |
| 页面 | `--surface` | `body`、吸顶头部、答题条 |
| 卡 | `--surface-raised` + `--line` 边框 | 独立内容单元 |
| 凹陷 | `--surface-sunken` | 卡内部的槽：输入框、进度轨、标签、光谱轨 |

头部和答题条用页面底色是因为它们要和页面同色才不露缝，这是唯一的例外。

**层级只能向内变深，不能反向。** 页面底色永远不作元素底色，凹陷层永远不出现在卡外面。
同级兄弟必须同层：一屏里并排的块不能一个凸一个凹。

浅色下 raised 和页面只差 1.04 的对比度，凹陷是 1.08。也就是说凹比凸更显眼，
所以凹陷层只留给「槽」，一旦拿它当并列卡片用，层级就读反了。

卡分两级，区别**只有阴影**，其余属性完全一致：

- 带 `--shadow-card`：`.card`、`.scene-hero`、`.checkout`、`.poster`（用 `--shadow-lift`）。整块内容单元。
- 不带阴影：`.gets`、`.angle`、`.scene-card`、`.type-cell`、`.type-line`、`.type-link`、`.dimension-scene`、`.share-preview`。网格里的并列格。

边框颜色跟随背景：中性底一律 `--line`，只有 `--scene-tint` 底才配 `--scene-line`。
面的令牌不作边框用。

渐隐遮罩的透明起点用 `--surface-fade` / `--surface-raised-fade`，不要写 `transparent`
也不要写别的颜色：老 WebKit 不做预乘插值，中段会透出灰边。

## 微信内置浏览器兼容

- 不用 `:has()`。
- 视口单位只用 `dvh` 且必须有 fallback，或者干脆不用。
- 不用需要降级兜底的新 CSS 特性。
- `localStorage` 读写全部包 try/catch，隐私模式下会抛异常。
- 深色模式跟随系统，微信本身的深色开关不一定透传，所以浅色必须独立成立。

## 无障碍

- 进度条带 `role="progressbar"` 和 `aria-valuenow`。
- 装饰性元素加 `aria-hidden`。
- 按钮最小触达 48px。
- 颜色不是唯一的状态指示，选中态同时改边框、背景和圆点。
