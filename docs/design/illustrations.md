# 情境插画规范

## 目的与边界

插画让用户在熟悉的生活片段里进入自我认知内容：精力从哪里恢复、看见哪些信息、如何权衡选择、怎样安排生活，以及如何理解彼此。它们承担内容导航与解释，不呈现用户真实得分。

2026-09 的插画扩展来自用户提供的青绿色人物插画风格参考。采用细轮廓、柔和青绿、轻微纸张颗粒和完整叙事场景，人物姿态、道具及构图均为原创。参考图不作为产品资源直接使用。

2026-09-08 起画面改为内联 SVG（`src/components/SceneArt.tsx`），形体改为扁平矢量：圆头、圆角躯干、可辨认的手和脚，道具用几何形。换成矢量的理由是每张图从 100KB 级降到 2KB 级、任意尺寸都清晰，以及可以给局部加轻微动画。v1 的 PNG/WebP 原画仍保留在 `public/illustrations/`，清单不再引用；`SceneIllustration` 保留 `<picture>` 分支，声明 `kind: "svg"` 之外的资源仍按位图渲染。

同一次改动里放开了单色限制：原来的青绿单色在手机上偏灰、偏淡，图小的时候几乎看不出画的是什么。现在每张图有自己的主色，人物的衣服、头发、肤色和道具都上色，见下面的「视觉语言」。

`TypeArt`、`TypePoster` 与分享卡继续使用类型码生成的固定几何。真实个人倾向仍由 `ScoreSpectrum` 表达，公开类型的示意位置仍有对应说明。插画不新增类型推断，不参与计分，也不表达更优或更差的偏好。

## 内容和资源

唯一清单为 `content/illustrations.json`，记录资产路径、版本、尺寸、替代文本、主题说明、维度映射与页面位置。组件读取清单，不在页面内硬编码场景与测试文案。完整原创生成提示词在 [illustration-prompts.json](./illustration-prompts.json) 留档，便于按同一风格续作。

| 场景 | 画面信息 | 主要位置 |
| --- | --- | --- |
| discovery | 观察不同情境下的自己 | 首页、测试介绍、结果核心描述 |
| energy | 独处与交流两种精力恢复方式 | 精力偏好卡、首页内容入口 |
| information | 细节观察与联想到更大的图景 | 信息偏好卡、认知章节 |
| decisions | 同时权衡逻辑与感受 | 决策偏好卡、首页内容入口 |
| rhythm | 确定计划与灵活探索 | 生活节奏卡 |
| growth | 用小行动照料成长 | 报告介绍、成长章节 |
| relationships | 理解不同表达与沟通方式 | 类型目录、相关类型、关系章节、类型页「友谊」 |
| love | 两个人并肩坐着，中间浮起一颗心 | 类型页「恋爱」 |
| career | 桌前工作与墙上逐级上升的看板 | 类型页「工作」、报告工作章节 |

矢量场景写在 `SceneArt.tsx` 里，`content/illustrations.json` 的 `assets.<scene>.art` 指向场景 id，`kind: "svg"` 决定走矢量分支。颜色常量写死在组件里，不跟随主题令牌：插画会被截图外发，深浅色模式下必须长得一样。新增场景要同时加画面、清单条目和替代文本，并检查所有引用位置。

位图路径仍然可用：资产放在 `public/illustrations/`，按 `<scene>-v1.png` 与 `<scene>-v1.webp` 成对保存，两种格式保持相同画幅与内容，不使用外部图片服务。

## 视觉语言

- 暖白纸面 `#fbfaf7` 打底。调色板有六个色系：青绿、天蓝、靛紫、玫红、琥珀、鲜绿，每个色系给「铺面 / 填形 / 压边 / 地面」四档，另有珊瑚橙作强调。饱和度停在明快的一档，不用荧光色，也不用促销红。
- **每张图一个主色故事。** 场景声明 `band`（整块底色）、`blob`（主体后的色块）、`ground`（地面）、`accent`（配景），彼此相邻但不同色；九张图放在一起靠同一张纸、同一套圆角形体和同一套人物保持成套。
- **人物是彩色的。** 衣服、裤腿、头发、肤色都是参数，三档肤色、四档发色轮换，脸上有腮红。同一张图里的两个人永远同样鲜亮，不用颜色暗示哪一边更好。
- 主体由人物动作和道具关系构成，避免大量无含义的星点与漂浮图标。
- 画面四周保留空气，关键物件靠近主体，缩小到 104px 仍能认出场景。
- 画内不绘制正文、标题或品牌文字，信息由 HTML 文案与替代文本提供。
- 画面颜色固定，外围 UI 跟随主题。插画不改变品牌靛蓝按钮和原有类型色板，两套色系各管各的。

## 两种画幅

| 画幅 | 比例 | 用在哪 |
| --- | --- | --- |
| `square` | 1:1 | 卡片、维度格、类型目录、答题页小图 |
| `banner` | 8:5 | 类型页的章节头图，铺满正文宽度 |

`banner` 在方形主体两侧补一条整幅底色、一条横贯的地面，以及左右两组配景（一株植物或几块石头、天上一个太阳/云/月亮）。主体本身是同一份画面，不为横幅重画。画面左边自带道具的场景把 `left` 设成 `stones`，免得两株植物撞在一起。

## 页面节奏

插画整体比 2026-09-07 那版放大了一档：封面 184px 起，正文卡片的图从 104px 提到 120px 上下，类型页的章节头图直接铺满正文宽度。图太小时人物动作看不出来，也就失去了「先看图再决定读不读」的作用。

首页和测试介绍先用一幅自我观察场景建立主题，再以多幅场景卡解释可探索的内容。首页的三张卡在手机上图左文右，让用户连续浏览；大屏改为三列。介绍页的四个维度用两列插画卡呈现，真实维度说明轴单独排在其后，避免在窄卡片里挤压两端标签。

首页与介绍页在 640px 以上扩到 54rem，封面采用左文字、右插画的双列。375px 手机封面插图为 184px，320px 宽度降到 144px，高度不超过 620px 的短屏降到 128px，保留开始按钮的优先级。正文插图约 88–104px，作为章节入口，避免每段都重复一张大图。

答题页仅在顶部展示通用自我观察小图，48px，且不随题目变化。680px 以下的短屏隐藏这行提示，原有题干与选项结构不变。结果页首屏继续聚焦类型码和标签；场景图位于后续的描述与报告介绍。

## 画面里的动画

每张图有三到五处动作，全部是 CSS 关键帧，不用 JS：

| 动作 | 用在哪 | 幅度与周期 |
| --- | --- | --- |
| 起伏 `scene-bob` | 人物 | 上下 8px，2.6s，同图里的人错开时间 |
| 挥手 `scene-wave` | `arms="wave"` 的那条胳膊 | 绕肩摆 -10°→18°，1s |
| 眨眼 `scene-blink` | 每个人的眼睛 | 竖向压到 8%，一轮 3.8s 里只占很短一段 |
| 摇摆 `scene-sway` | 植物、枝叶 | -7°→8°，3.4s |
| 转动 `scene-spin` | 太阳光芒 | 一圈 14s |
| 呼吸 `scene-breathe` | 太阳本体 | 缩放 1→1.09，3s |
| 飘动 `scene-float` / `scene-drift` | 对话气泡、便签、云 | 上下 11px 或左右 9px，3.2–6s |
| 心跳 `scene-beat` | 心形 | 1→1.18 两段回弹，1.8s |
| 落下 `scene-drop` | 水滴 | 淡入落下 26px，1.8s，三颗错开 |
| 升起 `scene-rise` | 看板柱子 | 上移 9px，2.6s，逐根错开 |
| 反光 `scene-glare` | 镜面 | 横扫 ±9px，3.6s |

**幅度调过一次。** 最早按 2–6px、3–8 秒做，用户反馈是「要仔细看才有效果」。现在的值是把幅度提到一眼能看见、又不至于让人分神的那一档。

三条约束不变：动作不承载信息，关掉之后画面照样说明主题；动作服务于画面主题，不做无意义的漂浮；`prefers-reduced-motion: reduce` 时全部静止。

SVG 里做旋转和缩放必须写 `transform-box: fill-box`，否则 `transform-origin` 相对整张画布，图形会飞出画面。这个属性从 Chrome 64 / Safari 11 起支持，在兼容基线之内。

## 可访问性与兼容

`SceneIllustration` 使用清单里的替代文本描述画面含义。不得以图中符号代替测试结论、按钮文字或付费边界说明。深色模式保持插画暖白画幅，正文采用可读的主题文字颜色。

矢量场景随 HTML 一起到达，不产生额外请求，也不需要预留空间。旁边已有等价文字时传 `decorative`，转成 `aria-hidden`，避免读屏重复播报；独立使用时用清单里的替代文本作 `aria-label`。

位图分支保持原有约定：`<picture>` 优先 WebP，PNG 作为旧内核回退；首屏图优先请求，折叠以下延迟加载；图片显式声明宽高，外容器用传统百分比内边距预留正方形空间。多列间距使用 CSS Grid，flex 场景继续使用 margin。

交付时运行 `npm run check:china`，并在 375px、320 × 568、桌面与深色模式中检查图片加载、横向溢出、主操作位置和答题选项可见性。

## 本轮验证记录（2026-09-07）

本轮浏览器实测采用浅色模式：375 × 812 的首页与介绍页首屏正常；320 × 568 的介绍页开始按钮底边位于 493px，答题页五个选项均可见且辅助插画隐藏；1280 × 900 的首页双列封面与三列场景卡正常。375px 报告页的四幅场景插画均加载且无横向溢出，320px 类型目录布局正常。

已实际完成 48 题作答，并经本地 mock 支付进入报告。`npm run ship` 通过，包含 18 项测试；构建后的 `npm run check:china` 为 0 个问题、3 条现有兼容提醒。深色模式本轮仅复核样式令牌，未做浏览器视觉实测；尚未进行国内设备与内置浏览器真机验证。
