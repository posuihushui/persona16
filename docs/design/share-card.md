# 分享卡

分享卡是获客物料，它的设计优先级高于站内任何页面。

## 三种分享形态

| 形态 | 来源 | 现状 |
| --- | --- | --- |
| 用户截图结果页首屏 | `.hero` 区块 | 已实现，是主要传播形态 |
| 微信 JS-SDK 分享缩略图 | 静态 PNG | 待接入，见下 |
| 页面 OG 图 | `/api/og?slug=&code=` 动态 SVG | 已实现 |

## 为什么 OG 图用 SVG

Next.js 的 `ImageResponse` 基于 Satori，渲染中文需要在服务端内嵌 CJK 字体。一个可用的中文字体子集在几 MB 量级，会明显拖慢冷启动和放大部署产物，而这条路径的收益只是一张缩略图。

所以 `/api/og` 返回 `image/svg+xml`，由客户端用系统字体渲染，中文显示正常。

代价是：微信 JS-SDK 的 `imgUrl` 只接受位图，SVG 在那里不生效。

## 微信分享缩略图的做法

需要为每个类型准备一张 300×300 的 PNG，放在 `public/share/<CODE>.png`。

生成方式，二选一：

**方案 A（推荐）** 用同一份 SVG 模板，在构建期批量转成 PNG。写一个 `scripts/build-share-images.mjs`，用无头浏览器截图 `/api/og?slug=persona16&code=XXXX`，输出到 `public/share/`。这样卡片样式只有一个真源。

**方案 B** 设计侧一次性导出 16 张 PNG，纳入版本管理。改样式时需要重新导出，容易和线上不一致。

在实现之前，JS-SDK 分享先统一使用站点级缩略图 `public/share/default.png`。这会损失一部分分享点击率，但不影响主要传播路径（用户截图）。

## 卡片构图

从上到下：

1. 测试名，小字，透明度 0.75
2. 类型码，最大字号，字间距 0.08em
3. 类型名
4. 人设标签
5. 三个关键词 chip

背景是从测试主色到深蓝 `#14162b` 的 160 度渐变。160 度让亮部集中在左上，类型码压在亮部上，缩略成小图时辨识度最高。

## 硬约束

- **不放二维码。** 带广告的图用户不愿意转发。
- **不放 logo 水印。** 同上。
- **不放用户的任何个人信息。** 卡片只有类型码和类型描述，任何人拿到这张图都无法反推是谁。
- **卡片要能独立成图。** 不依赖周围文字解释，单独看得懂。
- 类型码必须在结果页首屏可见，不需要滚动。

## 深浅色

卡片在深浅色模式下保持一致，因为它是要被截图外发的。`--hero-accent` 来自内容包的 `theme.accent`，是固定色值不是主题令牌，这是有意为之。

页面其余部分跟随系统主题。
