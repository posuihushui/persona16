# 分享卡

分享卡是获客物料，与结果页共用类型主视觉。当前实现以截图、保存图片和复制公开类型链接为主。

## 分享形态

| 形态 | 来源 | 状态 |
| --- | --- | --- |
| 首屏截图 | 紧凑的 TypePoster | 已实现 |
| 保存类型卡 | 同源 SVG 在浏览器转为 900×1200 PNG | 已实现，长按保存与下载入口 |
| 类型链接 | 当前访问域名下的 /t/<slug>/type/<code> | 已实现，接收者可开始自己的测试 |
| 系统分享 | 浏览器提供 navigator.share 时展示 | 已实现，取消不报错，失败可改用复制 / 卡片 |
| 页面 OG 图 | /api/og?slug=&code=&version= 动态 SVG | 已实现；不承诺所有平台都展示 SVG 缩略图 |
| 微信 JS-SDK 定制缩略图 | JS-SDK 配置与可公网访问的 PNG 地址 | 尚未接入，不能用浏览器 PNG 成功代替验收 |

## 构图与内容

主视觉、测试名、类型码、类型名、人设标签和三个关键词组成一张独立卡片。主视觉使用 `typeArtMarkup(code)`，色板来自 `toneFor(code)`；结果页、类型页与分享卡共用这一来源，颜色不随深浅色模式变化。

卡片不包含个人作答、四维实际位置、订单、查询码或付费正文；不放二维码和额外水印。链接只携带类型信息。用户自行截图更下方的四维位置属于主动展示，不能把这种截图与系统生成的类型卡混为一谈。

## 生成与兼容

点击保存才请求卡片，避免拖慢结果首屏。请求与图像加载超过 15 秒时结束等待并允许重试。成功后在当前页面复用 PNG；关闭预览再打开不重复请求。

图片保留为原始 `img`，微信里提示长按保存，抖音里补充浏览器打开指引。下载属性在不同 WebView 的行为需要真机验收，因此长按和截图入口同时保留。

复制先尝试 Clipboard API，失败再尝试传统复制；两者都不可用时展示可选中的链接。不得在复制失败时声称复制成功。系统分享调用完成也不能推断朋友已经收到链接。

## 后续微信缩略图接入

接入 JS-SDK 时，使用同一份类型几何导出位图，配置可公网访问的同源图片地址，并在正式域名完成签名和真机验证。当前本地 PNG 数据地址不能直接作为 JS-SDK 的分享缩略图地址。

## 验收

- 首屏类型码、标签、关键词可读，保存 / 复制按钮容易找到。
- 分享卡长按、下载、失败重试均有可见反馈。
- 免费用户无需支付或领取优惠也能保存卡片。
- 类型链接不包含个人结果 ID、个人得分、订单或查询码。
- 图片生成与复制动作只能记为分享意愿，实际传播效果要靠接收者访问衡量。
