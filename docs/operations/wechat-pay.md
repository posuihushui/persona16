# 微信支付接入

这份文档是接入手册。按顺序做完，微信内和微信外浏览器的支付都能跑通。

代码在 `src/lib/pay/wechat.ts`，接口约定在 `src/lib/pay/provider.ts`。密钥轮换单独见 [wechat-pay-key-rotation.md](./wechat-pay-key-rotation.md)。

---

## 一、先确认你有什么

微信支付不是注册个账号就能用。JSAPI 支付需要三样东西同时具备，缺一个都调不起来。

| 需要的东西 | 用途 | 前置条件 | 大概耗时 |
| --- | --- | --- | --- |
| 已备案的域名 | 支付授权目录、回调地址都必须是它 | 主体与营业执照一致 | 已完成 |
| 微信公众号（服务号） | 提供 AppID，以及拿 openid 的网页授权能力 | 企业主体，需微信认证，每年 300 元 | 认证 1 到 5 个工作日 |
| 微信支付商户号 | 收款主体 | 营业执照、法人身份证、对公账户或结算卡、经营场景资料 | 审核 1 到 5 个工作日 |

**订阅号不行。** 网页授权和 JSAPI 支付都要服务号。个人主体的公众号也拿不到微信支付。

如果暂时只有个体工商户执照，商户号可以申请，但部分行业类目会被要求补充资料。测试类站点在提交经营场景时如实填「H5 网页」并附上落地页截图即可。

## 二、申请与绑定

### 1. 申请商户号

在 [pay.weixin.qq.com](https://pay.weixin.qq.com) 提交。经营场景选「线上-网站」，填写你的落地页地址。审核通过后会收到商户号（mchid，10 位数字）和一封开户邮件。

按邮件指引完成签约和入账验证，否则商户号处于「未签约」状态，调接口会报 `NOAUTH`。

### 2. 把公众号和商户号绑起来

这一步最容易漏。没绑定的表现是调 JSAPI 直接报 `APPID_MCHID_NOT_MATCH`。

商户平台 → 产品中心 → AppID 账号管理 → 关联 AppID，填入公众号的 AppID。然后**去公众号后台确认这条关联申请**，两边都确认才生效。

### 3. 开通 H5 支付

微信外的浏览器（Safari、Chrome、部分安卓自带浏览器）走 H5 支付，需要单独开通。

商户平台 → 产品中心 → H5 支付 → 申请开通。开通后在「开发配置」里填写 **H5 支付域名**，填你的分发域名。

没开通的表现是调 `/v3/pay/transactions/h5` 返回 `INVALID_REQUEST`，提示该商户号未开通此功能。

## 三、后台需要配的四个地方

这四项分别管不同的事，配错了报的错完全不一样。逐项对着填。

| 配置项 | 位置 | 填什么 | 配错的表现 |
| --- | --- | --- | --- |
| 支付授权目录 | 商户平台 → 产品中心 → JSAPI 支付 → 支付配置 | `https://你的域名/r/` | 调起支付时提示「商家参数格式有误」 |
| H5 支付域名 | 商户平台 → 产品中心 → H5 支付 → 开发配置 | `你的域名` | H5 下单返回 `INVALID_REQUEST` |
| 网页授权域名 | 公众号后台 → 设置与开发 → 公众号设置 → 功能设置 | `你的域名`，需下载校验文件放到网站根目录 | 授权跳转报 `redirect_uri 域名与后台配置不一致` |
| JS 接口安全域名 | 同上 | `你的域名` | JS-SDK 分享功能失效，不影响支付 |

**支付授权目录必须以斜杠结尾，且是调起支付那个页面的目录。** 本项目调起支付的页面是 `/r/<attemptId>`，所以目录填 `https://你的域名/r/`。填成 `https://你的域名/` 也可以，范围更大。

## 四、密钥准备

微信支付 v3 有四类密钥材料，分工不同，别搞混。

### 1. APIv3 密钥（32 位，自己设定）

商户平台 → 账户中心 → API 安全 → 设置 APIv3 密钥。自己生成一个 32 位随机串并妥善保存，微信不提供找回。

用途：解密回调里的 `resource` 字段。

```bash
openssl rand -base64 24 | head -c 32
```

### 2. 商户 API 证书（微信生成，你下载）

商户平台 → 账户中心 → API 安全 → 申请 API 证书。按引导用微信的证书工具生成，会得到：

- `apiclient_key.pem` 商户私钥，**用于给请求签名**
- `apiclient_cert.pem` 商户证书
- **证书序列号**，40 位十六进制，在商户平台的证书列表里能看到

用途：`Authorization` 头的签名，以及 JSAPI 调起参数的 `paySign`。

### 3. 微信支付公钥（微信生成，你下载）

商户平台 → 账户中心 → API 安全 → 微信支付公钥。下载得到 `pub_key.pem` 和一个**公钥 ID**，形如 `PUB_KEY_ID_0117...`。

用途：验证微信回调的签名。回调头 `Wechatpay-Serial` 携带的就是这个公钥 ID。

> 2024 年之后新开的商户号统一使用「微信支付公钥」。更早的商户号可能还在用「平台证书」，那种情况下 `Wechatpay-Serial` 携带的是平台证书的序列号，配置方式完全一样，本项目的 serial 到 PEM 映射两种都支持。

### 4. 把 PEM 转成环境变量

PEM 是多行的，环境变量是单行，需要把换行转成 `\n`：

```bash
awk 'BEGIN{ORS="\\n"} {print}' apiclient_key.pem
```

把输出整体作为 `WECHAT_MCH_PRIVATE_KEY` 的值。平台公钥同理。

## 五、环境变量

| 变量 | 从哪来 | 示例形态 |
| --- | --- | --- |
| `PAY_PROVIDER` | 固定填 `wechat` | `wechat` |
| `WECHAT_APP_ID` | 公众号后台 → 基本配置 | `wx1234567890abcdef` |
| `WECHAT_APP_SECRET` | 同上，只显示一次，重置会让旧的失效 | 32 位十六进制 |
| `WECHAT_MCH_ID` | 商户号 | `1900000109` |
| `WECHAT_API_V3_KEY` | 自己设定的 32 位串 | 32 个字符 |
| `WECHAT_MCH_SERIAL_NO` | 商户 API 证书序列号 | 40 位十六进制 |
| `WECHAT_MCH_PRIVATE_KEY` | `apiclient_key.pem`，换行转 `\n` | `-----BEGIN PRIVATE KEY-----\nMII...` |
| `WECHAT_PLATFORM_PUBLIC_KEYS` | 公钥 ID 与 PEM 的映射，多个用 `;;` 分隔 | `PUB_KEY_ID_01=-----BEGIN PUBLIC KEY-----\n...` |
| `WECHAT_PAY_NOTIFY_URL` | 你的回调地址 | `https://你的域名/api/pay/notify/wechat` |

`WECHAT_PLATFORM_PUBLIC_KEYS` 的格式是 `序列号=PEM;;序列号=PEM`。轮换期必须同时保留新旧两个，见轮换文档。

配完跑两个检查：

```bash
npm run check:prod-env -- --env-file ./deploy/prod.env
npm run check:pay-rotation -- --env-file ./deploy/prod.env
```

`check:pay-rotation` 会用你的商户私钥做一次试签，私钥格式不对当场就能发现，不用等联调。

## 六、支付链路

三种环境走三条路，`detectScene()` 按 User-Agent 判断。

### 微信内（JSAPI）

```
用户点解锁
  → POST /api/order/create
  → 没有 openid？返回 { kind: "auth" }，前端跳 /api/wechat/auth
      → 微信静默授权 snsapi_base
      → 换 openid，写进签名 Cookie
      → 跳回结果页，用户再点一次解锁
  → 有 openid：调 /v3/pay/transactions/jsapi 拿 prepay_id
  → 用商户私钥签出 paySign，返回给前端
  → 前端 WeixinJSBridge.invoke('getBrandWCPayRequest', ...)
  → 用户输密码付款
  → 前端轮询 /api/order/{orderId}/status
  → 微信回调 POST /api/pay/notify/wechat（权益发放的依据）
```

### 微信外浏览器（H5）

```
用户点解锁
  → POST /api/order/create
  → 调 /v3/pay/transactions/h5 拿 h5_url
  → 拼上 redirect_url，前端整页跳转
  → 微信收银台唤起微信 App 完成支付
  → 跳回 redirect_url，也就是 /r/<attemptId>/report
  → 报告页发现未付费，先对账一次待支付订单再决定是否放行
  → 微信回调 POST /api/pay/notify/wechat
```

### 抖音内置浏览器

抖音的 WebView 无法唤起微信支付，也无法跳转到微信 App。这不是可以绕过的技术问题。

`prepay()` 在检测到抖音环境时返回 `kind: "unsupported"`，前端显示明确引导：点右上角在浏览器中打开，或复制链接到微信中打开。**不允许静默失败**，用户点了按钮没反应比明确告诉他去哪里更糟。

## 七、为什么必须有主动查单

回调会丢。网络抖动、服务重启、微信侧重试间隔，都会让回调晚到或不到。微信的重试策略是 15 秒后第一次，之后间隔递增，最长可能几小时。

用户在页面上等不了。所以：

- **权益发放的依据仍然只有回调和查单两条服务端路径**，前端的成功回调不算数。
- 前端支付成功后轮询 `/api/order/{orderId}/status`，服务端在订单仍是 PENDING 时向微信查单，把状态补上。
- H5 支付跳回报告页时，报告页也会先对账一次待支付订单，避免付了钱却被弹回结果页。

实现在 `src/lib/pay/reconcile.ts`。查单失败不会把订单判死，仍然保持 PENDING 等回调。

## 八、回调的三道防线

`src/app/api/pay/notify/[provider]/route.ts` 依次做四件事，任何一步不过都不发放权益。

1. **验签** — 用 `Wechatpay-Serial` 对应的平台公钥验证 `时间戳\n随机串\n请求体\n`。序列号没配置会直接报错并提示去看轮换文档。
2. **防重放** — 回调时间戳与当前时间偏差超过 5 分钟拒绝。
3. **幂等** — 把微信事件 id 写进 `PaymentEvent` 表，唯一索引冲突说明这个事件处理过，直接回 204。
4. **金额核对** — 回调金额与订单金额不一致直接拒绝，不发放权益。

回执约定：处理成功回 204 空响应，失败回 500 加 `{code:"FAIL"}`。回 200 但带内容微信也会认为失败并继续重试。

## 九、联调步骤

按这个顺序，每步都能独立验证，出问题知道卡在哪。

**第 1 步 本地跑通业务流程**

`PAY_PROVIDER=mock`，走一遍下单、支付、看报告、换设备找回。这一步不碰微信，只验证业务逻辑。

**第 2 步 验证密钥配置**

```bash
npm run check:pay-rotation -- --env-file ./deploy/staging.env
```

私钥能试签、公钥能解析、回调地址是 https，这三项通过再往下。

**第 3 步 验证网页授权**

部署到已备案域名，微信内打开 `https://你的域名/api/wechat/auth?next=/`。应该无感跳转一圈回到首页，并且浏览器里多了一个 `p16_wx` Cookie。

失败最常见的原因是网页授权域名没配，或校验文件没放到网站根目录。

**第 4 步 验证预下单**

微信内点解锁。看服务端日志，`/v3/pay/transactions/jsapi` 应该返回 `prepay_id`。

这一步报错的话，错误码直接对应第十节的排查表。

**第 5 步 真实小额支付**

把 `paywall.json` 的 `price.amount` 临时改成 `1`（1 分钱），完整付一次。确认：

- 收银台正常唤起
- 支付后前端轮询到已支付
- 服务端收到回调，`PaymentEvent` 表有记录
- `Order` 状态变成 PAID，报告可以打开

**第 6 步 验证回调幂等**

在商户平台重新推送一次回调，或者用日志里的请求体重放一次。确认 `PaymentEvent` 表没有新增记录，权益也没有重复发放。

**第 7 步 验证退款**

```bash
npm run refund -- --order <订单号> --reason "联调验证" --operator 你的名字
```

不加 `--yes` 是预演。确认信息无误后加 `--yes` 执行，然后在商户平台核对退款记录。

**第 8 步 改回正式价格**

别忘了把 `price.amount` 改回去，并重新跑 `npm run check:content`。

## 十、错误排查

### 下单阶段

| 错误码或提示 | 真实原因 | 怎么修 |
| --- | --- | --- |
| `APPID_MCHID_NOT_MATCH` | 公众号和商户号没绑定，或只单边确认了 | 商户平台关联 AppID，去公众号后台确认 |
| `NOAUTH` | 商户号未签约或未开通对应产品 | 检查开户邮件的签约流程，确认 JSAPI / H5 支付已开通 |
| `SIGN_ERROR` | 签名串拼错，或私钥与序列号不匹配 | 跑 `check:pay-rotation`；确认签名串五行结尾都有换行 |
| `INVALID_REQUEST` 提示未开通 | H5 支付没开通 | 商户平台申请开通 H5 支付并配置域名 |
| `OUT_TRADE_NO_USED` | 同一个订单号重复下单且金额不同 | 本项目订单号是数据库主键，不会重复；出现说明重试逻辑有问题 |
| `ORDERPAID` | 订单已支付 | 直接查单同步状态，不要报错给用户 |
| `PARAM_ERROR` 指向 `payer_client_ip` | H5 下单没传真实用户 IP | 检查反向代理是否透传 `X-Forwarded-For` |

### 调起阶段

| 现象 | 真实原因 | 怎么修 |
| --- | --- | --- |
| 「商家参数格式有误，请联系商家解决」 | 支付授权目录没配或配错 | 商户平台填 `https://你的域名/r/`，注意结尾斜杠 |
| 「调用支付 JSAPI 缺少参数」 | 同上，微信这个提示有误导性 | 同上 |
| `WeixinJSBridge is not defined` | 页面在微信外打开，或 JSBridge 还没注入 | 本项目已判断并给出引导；不要在 DOMContentLoaded 之前调用 |
| 收银台白屏 | openid 不属于这个 AppID | 确认拿 openid 用的 AppID 与下单用的是同一个 |

### 回调阶段

| 现象 | 真实原因 | 怎么修 |
| --- | --- | --- |
| 日志里「未配置 Wechatpay-Serial 对应的平台公钥」 | 微信换了签名用的公钥，你只配了旧的 | 见轮换文档，新旧同时保留 |
| 「回调验签失败」 | 读请求体时被中间件改动过 | 验签必须用原始 body 文本，不能先 JSON 解析再序列化 |
| 微信一直重试 | 你回了 200 但带内容，或回了非 2xx | 成功必须回 204 空响应 |
| 回调到了但权益没发 | 金额核对没过 | 查日志里的金额对比，通常是测试期改过价格 |

## 十一、对账

微信每天上午出前一天的账单。建议每天核对一次，重点看两类差异：

- **微信有你没有** — 用户付了钱但你的库里是 PENDING。通常是回调丢了且用户没回来触发查单。补救办法是对这些订单批量查单。
- **你有微信没有** — 你的库里是 PAID 但账单里没有。这种情况必须查清楚，可能是状态被错误写入。

下载路径：商户平台 → 交易中心 → 交易账单。也可以调 `/v3/bill/tradebill` 接口自动化。

本项目暂未实现自动对账。上量之前每天手工核一次成本很低，上量之后再做自动化。
